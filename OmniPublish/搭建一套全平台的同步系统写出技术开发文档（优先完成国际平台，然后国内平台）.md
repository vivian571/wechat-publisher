**项目代号：OmniPublish 自动化发布系统架构文档**

## **1\. 系统概述 (System Overview)**

本系统旨在实现“**一次编写，到处发布**” (Write Once, Publish Everywhere)。通过统一的 Markdown 解析核心，对接不同平台接口，实现技术文章的自动化分发、元数据管理及图片图床的统一处理。

**2\. 核心模块设计 (Core Modules)**

在开发具体平台适配器前，必须先完成以下通用模块的开发：

1. **Article Parser (文章解析器)**:  
   * 利用 gray-matter 解析 Markdown 头部的 YAML Frontmatter（标题、标签、封面图、发布时间）。  
   * **关键逻辑**: 必须处理不同平台的标签映射（例如：Dev.to 需要 tag list，Medium 需要 tag string）。  
2. **Asset Manager (资源管理器)**:  
   * **痛点**: 本地图片路径 (./img/1.png) 无法被 API 识别。  
   * **方案**: 自动扫描 Markdown 内图片 \-\> 上传至 AWS S3/阿里云 OSS/Cloudflare R2 \-\> 替换 Markdown 内链接为公共 URL。  
3. **Canonical URL Generator (SEO 优化)**:  
   * 确定一个“主站”（如个人博客），其他平台发布时必须在 Payload 中注入 canonical\_url，防止被搜索引擎判定为重复内容。

## ---

**3\. Phase 1: 国际平台适配器 (International Platforms)**

**优先级：P0** | **技术栈：Node.js (Axios/Fetch)**

此阶段利用官方标准 API，稳定性高，易于维护。

### **3.1 Dev.to Adapter**

* **Auth**: API Key (Header: api-key)  
* **Endpoint**: POST https://dev.to/api/articles  
* **Payload 结构**:  
  JSON  
  {  
    "article": {  
      "title": "文章标题",  
      "body\_markdown": "Markdown 内容...",  
      "published": true,  
      "tags": \["javascript", "automation"\],  
      "series": "系列名(可选)",  
      "canonical\_url": "主站链接"  
    }  
  }

* **注意**: 接口限流较为宽松，建议重试机制设为 3 次。

### **3.2 Hashnode Adapter**

* **Auth**: Personal Access Token (Header: Authorization)  
* **Endpoint**: POST https://api.hashnode.com (GraphQL)  
* **核心**: Hashnode 使用 GraphQL，需要构造 Mutation。  
* **GraphQL Query 示例**:  
  GraphQL  
  mutation createPublicationStory {  
    createPublicationStory(  
      publicationId: "YOUR\_PUB\_ID",  
      input: {  
        title: "Title",  
        contentMarkdown: "Content...",  
        tags: \[...\]  
      }  
    ) { ... }  
  }

### **3.3 Medium Adapter**

* **Auth**: Integration Token (Header: Authorization: Bearer \<token\>)  
* **Endpoint**: POST https://api.medium.com/v1/users/{{userId}}/posts  
* **限制**: Medium API 创建的文章默认为 "Draft"（草稿）或 "Unlisted"，且不支持直接更新已发布文章（只能创建新文章）。  
* **策略**: 建议设为 publishStatus: "draft"，人工确认后再发布。

**4\. Phase 2: 国内平台适配器 (Domestic Platforms)**

**优先级：P1** | **技术栈：Playwright / 逆向私有 API**

国内平台防爬机制严格，需采用“Cookie 持久化”或“浏览器自动化”方案。

### **4.1 认证中心 (Auth Center)**

* **Cookie Pool**: 不建议每次发布都登录。开发一个本地脚本，开发者手动登录一次，提取 Cookie (JUEJIN\_COOKIE, CSDN\_COOKIE) 存入 GitHub Secrets 或 .env 文件。

### **4.2 稀土掘金 (Juejin)**

* **方案**: 逆向私有 API (比 Puppeteer 更快更稳)。  
* **Endpoint**: POST https://api.juejin.cn/content\_api/v1/article/publish  
* **关键 Headers**: cookie, x-secsdk-csrf-token (需从 Cookie 中解析)。  
* **Markdown 处理**: 掘金对 Markdown 的换行和代码块渲染有特殊逻辑，需在发送前进行预处理（Pre-flight cleaning）。

### **4.3 微信公众号 (WeChat Official)**

* **方案**: 官方 API (草稿箱能力)。  
* **Endpoint**: POST https://api.weixin.qq.com/cgi-bin/draft/add?access\_token=ACCESS\_TOKEN  
* **痛点**: 微信不支持 Markdown。  
* **解决方案**:  
  1. 使用 markdown-to-wechat 转换库，将 MD 转为微信特定的 HTML 格式。  
  2. 上传文章中的图片到微信素材库，获取 media\_id 或微信域名的 URL（外链图片在微信中无法显示）。  
  3. 推送到草稿箱，**不要自动群发**（风险太高），仅做草稿同步。

### **4.4 CSDN / 知乎**

* **方案**: Playwright (浏览器自动化)。  
* **逻辑**:  
  1. 启动 Headless Browser。  
  2. 注入 Cookies。  
  3. 导航至创作中心 /editor。  
  4. 模拟剪贴板粘贴 Markdown 内容。  
  5. 监听“保存成功”或“发布”按钮。

**给 Antigravity 开发者的特别备注：**

⚠️ **关于风控**：国内平台的适配器请务必加入 Random Delay (随机延时)，例如在请求之间暂停 2-5 秒，防止被识别为机器人封号。对于知乎和 CSDN，建议仅使用 Playwright 模拟真实用户行为，不要尝试暴力破解 API 签名。
