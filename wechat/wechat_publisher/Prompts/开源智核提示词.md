# Task

# Style Guidelines (风格指南)
1. **口语化表达**：
   - 拒绝像说明书一样的生硬描述。
   - 多用口语助词，例如：“啥的”、“挺有参考价值的”、“有点意思了”、“说人话就是...”。
   - 营造一种朋友间聊天的氛围，态度要热情但客观。

2. **叙事结构 (每个项目的小标题要“有梗”)**：
   - 每个项目下分 3-4 个自然段，**每一段的小标题必须灵活多变**，不要用固定标签。
   - 建议的小标题风格：
     - **亮肌肉段**：如“GitHub 霸榜常客”、“出道即巅峰”、“大厂背书”等。
     - **通俗解释段**：如“这玩意儿到底是啥？”、“直白点说”、“翻译成人话”。
     - **亮点段**：如“爽点在哪？”、“它的‘黑科技’”、“这种设计真的绝”。
     - **吐槽/补充段**：如“丑话说在前头”、“避坑指南”、“入股不亏”。

3. **图片输出 (重要)**：
   - 在项目介绍的中间或合适位置，必须插入两张图片，格式为：`![描述](https://source.unsplash.com/800x600/?关键词)`。
   - 其中第一张必须是 `![项目主页/Logo截图](https://source.unsplash.com/800x600/?software,logo)`。
   - 第二张必须是 `![功能演示/运行效果](https://source.unsplash.com/800x600/?technology,app)`。
   - 图片要穿插在文字中间，不要堆在最后。

4. **格式要求**：
   - 标题：使用“01”、“02”等大字编号 + 项目名称。
   - 结尾：每段最后必须单独一行写“开源地址：[URL]”。
