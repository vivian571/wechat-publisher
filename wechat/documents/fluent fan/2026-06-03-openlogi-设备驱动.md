### 底层大白话：什么是“HID 物理数据监听”？

对于不懂硬件协议的小白同学，我们用最简单的大白话来拆解一下：
当你在鼠标上按下左键、右键或侧键时，鼠标芯片就会源源不断地向你的电脑发送一串串二进制的“秘密电波”（硬件里叫 **HID 报告描述符**）。

1. **官方驱动的“中介做法”**：
   官方 Options+ 驱动就像一个庞大的外包中介。它使用 Electron（本质上是在你后台偷偷开了一个 Chrome 浏览器）接收这些数据包，再经过一大堆冗余的 UI 层、网络同步层、配置校验层，最后才慢吞吞地把你的按键转换成系统操作。
   由于中介太多、体积太大，经常会因为网络波动或内存泄露而卡死！
2. **OpenLogi 的“直连做法”**：
   OpenLogi 是一个冷酷的原生接口监听器。它直接调用 macOS 的 `IOHIDManager` 或 Linux 的 `evdev` 底层文件接口。
   没有任何中间商赚差价。一旦听到侧键被按下的秘密电波，立刻通过 Rust 进行物理映射，瞬间模拟出你设置的系统热键。
   没有内存开销、没有延迟，每一次按键都清脆利落！

### 双核/双极驱动：原生HID描述符解析层与事件分发网关

OpenLogi 的超高性能主要由两大底层引擎所支撑：

1. **HID 描述符解析层（HID Parser Engine）**：
   直接对接到操作系统的物理 USB/蓝牙管道。监听所有罗技外设特有的十六进制命令包，过滤非目标设备信息，保留原始键值。
2. **事件分发网关（Event Mapping Dispatcher）**：
   读取用户自定义的 TOML 配置文件。在内存中建立高速的“键值-指令”映射表，在硬件按键触发的瞬间，通过系统原生模拟 API 毫秒级分发事件。

### 极简源码：手搓 100 行外设监听中心

请将以下完整源码保存为 `openlogi_listener.py`。该脚本使用 Python 原生逻辑模拟了 HID 数据包提取与 TOML 键值映射自验过程。

```python
import os
import sys

class OpenLogiHIDEngine:
    """手搓外设 HID 硬件事件监听与映射引擎"""
    def __init__(self, config_toml):
        self.config = config_toml
        self.log_stream = []

    def mock_hid_event_stream(self):
        """模拟物理硬件发送的 HID 原始二进制信号流"""
        # 模拟鼠标侧滚轮向上、侧后退键按下
        return [
            {"device_id": "0x046d", "raw_bytes": "05 1F 00 01"},  # 侧轮向上
            {"device_id": "0x046d", "raw_bytes": "05 1F 00 03"},  # 后退键按下
            {"device_id": "0x0999", "raw_bytes": "00 00 00 00"}   # 噪音干扰设备信号
        ]

    def parse_hid_bytes(self, event):
        """工作流一：物理描述符解析层，提取设备 ID 与原始指令"""
        if event["device_id"] != "0x046d":
            return None  # 忽略非罗技设备信号
        
        # 解析原始字节流
        raw = event["raw_bytes"]
        if raw == "05 1F 00 01":
            return "thumb_wheel_up"
        elif raw == "05 1F 00 03":
            return "button_back"
        return None

    def dispatch_event(self, key_action):
        """工作流二：读取映射配置，进行系统原生按键分发"""
        if not key_action:
            return
        
        mapped_action = self.config.get(key_action)
        if mapped_action:
            execution_msg = f"[✔] 硬件触发: {key_action} -> 映射系统指令: 执行 '{mapped_action}'"
            print(execution_msg)
            self.log_stream.append(mapped_action)

if __name__ == "__main__":
    print("[⚙] 正在启动 OpenLogi 硬件映射网关自验程序...")

    # 1. 模拟 TOML 配置文件载入
    mock_config = {
        "thumb_wheel_up": "VolumeUp",
        "button_back": "Ctrl+Left"
    }

    # 2. 初始化监听引擎
    engine = OpenLogiHIDEngine(mock_config)

    # 3. 消费硬件事件流
    events = engine.mock_hid_event_stream()
    for event in events:
        action = engine.parse_hid_bytes(event)
        engine.dispatch_event(action)

    # 自验条件：必须成功映射并执行了 "VolumeUp" 和 "Ctrl+Left" 两条指令
    if "VolumeUp" in engine.log_stream and "Ctrl+Left" in engine.log_stream:
        print("\n[✔] 自验成功！本地原生 HID 设备描述符监听与 TOML 分发逻辑 100% 收拢！")
        sys.exit(0)
    else:
        print("\n[❌] 自验失败：按键映射漏失！")
        sys.exit(1)
```

### 保姆级部署：如何在你的 macOS 上运行？

1. **安装 Rust 底座**：打开终端，安装 Rust 编译器：
   ```bash
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```
2. **克隆项目并编译**：
   ```bash
   git clone https://github.com/AprilNEA/OpenLogi.git
   cd OpenLogi
   cargo build --release
   ```
3. **编辑本地配置文件**：
   在 `~/.config/openlogi/config.toml` 中配置你的按键规则：
   ```toml
   [devices.mx_master]
   name = "MX Master 3S"
   thumb_wheel_up = "VolumeUp"
   button_back = "Ctrl+Left"
   ```
4. **启动后台守护进程**：直接运行编译好的二进制文件 `./target/release/openlogi`，即刻享受微秒级物理直连！

### 避坑指南与行业瓶颈

#### 🛠 避坑指南：
1. **避开系统安全拦截大坑**：由于 OpenLogi 需要监听系统底层的 HID 事件，在 macOS 上会触发“安全隐私保护”阻拦。**解决办法**：在运行守护进程前，必须在 macOS 系统设置的“辅助功能（Accessibility）”和“输入监听（Input Monitoring）”里，显式给该守护进程勾选授权，否则会无声卡死。
2. **避开蓝牙休眠后重连失效坑**：很多鼠标在静止 5 分钟后会自动进入低功耗蓝牙休眠。当它重新苏醒时，物理设备句柄发生了漂移，导致驱动程序找不到原设备。**解决办法**：在配置文件中，不能硬编码死设备的具体物理地址，而是配置设备名模糊匹配（如 `MX Master*`），让守护进程在断线后自动重试并拉取新句柄。
3. **避免 TOML 语法转义字符坑**：配置模拟键盘输入时，如果要发送类似 `Ctrl+Option+Shift+S` 等超长组合键，如果没做标准的特殊字符转义，OpenLogi 解析时会直接抛出非法字符异常。**解决办法**：组合键应严格使用标准的 TOML 字符串数组或规定的连接符形式，并在部署前运行 `openlogi --check-config` 进行静态语法自检。

#### ⚠️ 行业瓶颈：
虽然 OpenLogi 凭借 Rust 带来了微秒级的高速与极致的低能耗，但它的瓶颈也十分明显——**完全不支持官方 Flow 跨屏复制功能**。
官方的 Logitech Flow 底层依赖的是一套闭源的局域网局内多设备通信协议，这种大厂私有的上层协议很难通过简单的开源 HID 拦截来实现。如果你是一个需要频繁多屏跨主机无感复制的重度用户，那么在这个功能上，你依然无法完全摆脱官方 Options+ 的掌控。
