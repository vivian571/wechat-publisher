## 3. 核心本质：线程互斥锁与正则黑名单物理过滤

这套防御系统的底层原理极其精简、牢固，由两个铁律筑起防线：

### 铁律一：线程互斥锁（Mutex Lock）与持久化同步
当多个 Agent 并发运行时，读写本地 JSON 缓存文件会产生**“竞态条件”（Race Condition）**。
如果 Agent A 正在写入 JSON，而 Agent B 同时读取，文件内容就会发生断裂错位，导致解析报错。
我们使用 Python 内置的 `threading.Lock`。当任何线程试图写入缓存时，必须首先获取这把物理锁，其他线程只能在队列中安静等待。
**这保证了本地缓存数据在并发状态下的绝对原子性与完整性！**

### 铁律二：物理级命令行文本过滤（Regex Interception）
大模型输出的代码和命令在被送入 `subprocess.run` 或 `os.system` 执行之前，全都是纯文本。
我们在底层架设一个正则过滤器，在文本层面对命令进行多维碰撞。
**只要文本中匹配到 `rm -rf`、`chmod 777` 或 `mv ... /dev/null` 等高危特征，过滤器在毫秒级内直接抛出 SecurityException，从根本上杜绝命令在系统内核中被执行的可能！**

### 第一步：编写核心缓存与安全网关脚本

请在本地新建文件 `/Users/ax/wechat-publisher/agent-skills/agent_guard.py` 并写入以下全部可执行代码：

```python
import json
import os
import re
import threading
import sys

class AgentMemoryCache:
    def __init__(self, cache_filepath):
        self.cache_filepath = cache_filepath
        self.lock = threading.Lock()
        self.cache_data = {}
        self._load_cache()

    def _load_cache(self):
        """线程安全地加载本地缓存文件"""
        with self.lock:
            if os.path.exists(self.cache_filepath):
                try:
                    with open(self.cache_filepath, "r", encoding="utf-8") as f:
                        self.cache_data = json.load(f)
                except Exception:
                    self.cache_data = {}
            else:
                self.cache_data = {}

    def get(self, key):
        """从内存缓存中获取记录，避免重复调用大模型"""
        with self.lock:
            return self.cache_data.get(key)

    def set(self, key, value):
        """线程安全地写入内存并同步持久化到本地 JSON"""
        with self.lock:
            self.cache_data[key] = value
            try:
                with open(self.cache_filepath, "w", encoding="utf-8") as f:
                    json.dump(self.cache_data, f, ensure_ascii=False, indent=4)
            except Exception as e:
                print(f"[❌ 写入缓存失败]: {e}")


class BashCommandGuard:
    def __init__(self):
        # 严格定义的系统高危高毒命令正则黑名单，拒绝任何占位符
        self.blacklist = [
            (re.compile(r"\brm\s+-rf\b"), "高危删库指令拦截！严禁在系统上执行递归强制删除 rm -rf！"),
            (re.compile(r"\bchmod\s+(?:-R\s+)?777\b"), "高危权限破坏拦截！严禁执行 chmod 777 破坏系统权限防线！"),
            (re.compile(r"\bmv\s+.*\s+/dev/null\b"), "高危垃圾销毁拦截！严禁将系统资产移动至 /dev/null 空设备中！"),
            (re.compile(r"\b:>|>\s*/etc/passwd\b"), "高危系统重写拦截！严禁篡改或重写系统核心敏感配置文件！")
        ]

    def execute_safely(self, command):
        """执行前置安全审计，通过后方可执行模拟提交"""
        stripped_cmd = command.strip()
        print(f"[🔍 审计中] 正在对命令进行物理特征碰撞: '{stripped_cmd}'")
        
        # 遍历黑名单规则碰撞
        for pattern, alert in self.blacklist:
            if pattern.search(stripped_cmd):
                print(f"[🚨 安全门禁硬阻断]：{alert}")
                return False
                
        print(f"[✔ 审计安全] 命令通过安全关卡，准予送入物理 Shell 执行！")
        return True


# ==================== 仿真运行与测试驱动入口 ====================
if __name__ == "__main__":
    cache_path = "./agent_action_cache.json"
    
    print("[⚙] 初始化 Agent 安全性能双防线系统...")
    cache_system = AgentMemoryCache(cache_path)
    command_guard = BashCommandGuard()

    print("\n--------------------------------------------------")
    print("[🔥 演示一：本地零 Token 缓存命中测试]")
    
    # 模拟 Agent 遇到的高频高重复询问
    test_prompt = "请问 Python 中的列表和元组有什么本质区别？"
    
    # 第一次尝试读取，未命中缓存，模拟消耗 Token 调用 API
    cached_res = cache_system.get(test_prompt)
    if cached_res is None:
        print("[⚡ 缓存未命中] 正在向大模型 API 发起网络请求 (消耗真实 Token)...")
        real_api_response = "列表是动态可变数组，元组是静态不可变链表结构。"
        cache_system.set(test_prompt, real_api_response)
        print(f" 大模型返回内容: {real_api_response}")
    
    # 第二次尝试读取完全相同的 Prompt，命中缓存，免除网络消耗
    print("\n[⚡ 再次发起完全相同的 Prompt 询问...]")
    cached_res_2 = cache_system.get(test_prompt)
    if cached_res_2:
        print("[🎉 极速命中本地缓存！] 0 延迟，0 成本 Token，直接读取本地数据:")
        print(f" 本地缓存内容: {cached_res_2}")

    print("\n--------------------------------------------------")
    print("[🔥 演示二：高危 Bash 命令硬拦截测试]")
    
    # 模拟大模型幻觉或者恶意注入后生成的两条命令
    safe_command = "python3 --version"
    toxic_command = "rm -rf /var/log/nginx/*"

    # 执行安全命令
    success_1 = command_guard.execute_safely(safe_command)
    
    # 执行有毒命令，触发阻断
    success_2 = command_guard.execute_safely(toxic_command)

    # 自动清理仿真产生的本地缓存文件，保持用户系统干净清爽
    if os.path.exists(cache_path):
        os.remove(cache_path)

    # 如果有毒命令没有被成功拦截，说明防线崩溃，以错误状态码退出
    if success_1 and not success_2:
        print("\n[✔ 系统运行结论] 双防线全部运转完美，安全阻断机制 100% 成立！")
        sys.exit(0)
    else:
        print("\n[❌ 致命错误] 安全阻断发生漏报！")
        sys.exit(1)
```

## 6. 避坑指南：Agent 控制系统的三大暗礁

* **避坑 1：缓存淘汰机制（LRU）的缺席导致本地硬盘撑爆。** 如果你的 Agent 运行了几个月，处理了上亿条不同的 Prompts，本地 JSON 缓存文件会膨胀到几个 GB，每次加载内存直接耗尽。**针对大型项目，必须引入缓存有效期与 LRU 淘汰机制，设定最大文件大小为 100MB，超期自动清理！**
* **避坑 2：混淆命令包装（Obfuscated Shell Commands）导致的漏报。** 狡猾的黑客会把高危命令写成 `echo rmi -rf | sed ...` 或者是用 `base64` 编码后通过管道执行 `base64 -d | sh`。**安全门禁绝对不能仅做简单的字面正则匹配，必须对包含 `sh`、`bash`、`eval` 以及管道符号的复合指令进行多层递归解码审计！**
* **避坑 3：并发读写瞬间锁死导致的“死锁崩溃”。** 如果缓存锁 `self.lock` 的持有时间过长（比如在锁内部进行网络 I/O 或大文件持久化），会导致高并发下的其他 Agent 线程全部超时被挂死。**锁的粒度一定要小！只把读写内存 dict 的几微秒包在锁里，具体的持久化 IO 动作应移出锁或放到后台异步守护线程里跑！**
