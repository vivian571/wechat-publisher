### 底层大白话：什么是“两跳人脉关系”？

图数据库（Graph Database）听起来非常玄乎，其实它的底层物理世界只有两个极简概念：
- **节点（Node）**：就是宇宙里的每一个实体，比如你、你的朋友、某家公司、或者某次会议。
- **边（Edge/Relationship）**：就是把这些实体连起来的线，比如“是好友”、“是前同事”、“是前雇主”。

在现实社交圈里，有一个非常著名的理论叫 **六度分割理论（Six Degrees of Separation）**：你和世界上任何一个陌生人之间，最多只隔着六个人。
而在日常生活中，对我们价值最高的，就是**“两跳人脉（Two-hop Network）”**。
两跳人脉用人话说，就是**“朋友的朋友”**。
比如，你想结识某家新能源公司的技术总监，你自己不认识他，但是你发现你的死党 Bob 经常和这个总监（Charlie）一起打球。
如果直接把关系网存在一般的表格里，你要查出这一层关系需要写极其复杂的死循环。
但在图数据库里，我们给每个人与人之间的关系赋予一个**亲密度权重（Weight）**（比如：你和死党 Bob 是 0.9，Bob 和总监 Charlie 是 0.8）。
网关启动**二阶多跳路径扫描（Traversal）**，顺着你向外发散的线，找到 Bob，再顺着 Bob 往外延伸的线找到 Charlie。
通过计算两条线的乘积（`0.9 * 0.8 = 0.72`），系统瞬间就能在这个人脉网里标出：**“Charlie 是你的二级人脉，连接热度高达 0.72，通过 Bob 介绍成功率最高！”**
**这，就是图数据库在离线状态下的强悍穿透力！**

### 双翼对齐：有向拓扑建模与多跳能谱分析

本引擎的核心图解析算法由以下两个相互咬合的离线工作流组成：

1. **工作流一：SQLite 拓扑图网络有向边物理写入大闸（add_node & add_edge）**
   建立起节点表（id, 节点类型）与有向边表（来源ID, 目标ID, 关系类型, 亲密度权重）的强约束关系，物理连接并构建出完整的离线拓扑有向图。

2. **工作流二：多跳路径图遍历与社交漏斗能谱计算器（traverse_two_hops）**
   执行高精度的多表自连接 SQL 路径扫描，直接穿透一级好友屏障，拉出所有潜在的二级目标人脉，计算并由高到低排序二级关系热度得分。

### 极简源码：手搓 100 行本地人脉图数据库

请将以下完整源码保存为 `twenty.py`。完全零外部依赖，macOS 终端即刻一键秒级编译运行！

```python
import sqlite3
import sys

class OfflineGraphDatabase:
    """基于 SQLite 的个人离线关系图数据库引擎"""
    def __init__(self, db_path=":memory:"):
        self.conn = sqlite3.connect(db_path)
        self._init_db()

    def _init_db(self):
        cursor = self.conn.cursor()
        # 创建节点表 (存储实体：如联系人、公司)
        cursor.execute("""
            CREATE TABLE IF NOT EXISTS nodes (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                name TEXT UNIQUE NOT NULL,
                type TEXT NOT NULL
            )
        """)
        # 创建有向边表 (存储节点之间的关系与亲密度权重)
        cursor.execute("""
            CREATE TABLE IF NOT EXISTS edges (
                from_id INTEGER NOT NULL,
                to_id INTEGER NOT NULL,
                type TEXT NOT NULL,
                weight REAL NOT NULL,
                PRIMARY KEY (from_id, to_id, type),
                FOREIGN KEY (from_id) REFERENCES nodes(id),
                FOREIGN KEY (to_id) REFERENCES nodes(id)
            )
        """)
        self.conn.commit()

    def add_node(self, name, node_type):
        """插入或更新一个节点"""
        cursor = self.conn.cursor()
        cursor.execute("""
            INSERT OR IGNORE INTO nodes (name, type)
            VALUES (?, ?)
        """, (name, node_type))
        self.conn.commit()
        # 查找该节点 ID
        cursor.execute("SELECT id FROM nodes WHERE name = ?", (name,))
        return cursor.fetchone()[0]

    def add_edge(self, from_name, to_name, rel_type, weight=1.0):
        """工作流一：物理连接并写入具有向图（Directed Graph）节点与关系的拓扑网络"""
        from_id = self.add_node(from_name, "Person")
        to_id = self.add_node(to_name, "Person")
        
        cursor = self.conn.cursor()
        cursor.execute("""
            INSERT OR REPLACE INTO edges (from_id, to_id, type, weight)
            VALUES (?, ?, ?, ?)
        """, (from_id, to_id, rel_type, weight))
        self.conn.commit()

    def traverse_two_hops(self, start_name):
        """工作流二：执行多跳路径扫描，解算二级间接关系热力链路"""
        start_id = self.add_node(start_name, "Person")
        cursor = self.conn.cursor()
        
        # 二步图扫描 SQL（直接关联查两跳好友的“好友的好友”，排除自己）
        cursor.execute("""
            SELECT 
                n_start.name AS 起点,
                n_middle.name AS 中介好友,
                n_end.name AS 间接目标,
                e1.weight * e2.weight AS 二级关系热力得分
            FROM edges e1
            JOIN edges e2 ON e1.to_id = e2.from_id
            JOIN nodes n_start ON e1.from_id = n_start.id
            JOIN nodes n_middle ON e1.to_id = n_middle.id
            JOIN nodes n_end ON e2.to_id = n_end.id
            WHERE e1.from_id = ? 
              AND e2.to_id != ? 
              AND e2.to_id != e1.from_id
            ORDER BY 二级关系热力得分 DESC
        """, (start_id, start_id))
        
        return cursor.fetchall()

if __name__ == "__main__":
    print("[⚙] 正在启动个人离线关系图数据库 (Twenty-Graph) 自验测试...")

    # 1. 初始化内存图数据库
    db = OfflineGraphDatabase()

    # 2. 启动工作流一：向拓扑图数据库写入有向节点与关系权重
    # 模拟关系网：Alice -> Bob (0.9), Bob -> Charlie (0.8), Bob -> David (0.5)
    db.add_edge("Alice", "Bob", "Friend", 0.9)
    db.add_edge("Bob", "Charlie", "Colleague", 0.8)
    db.add_edge("Bob", "David", "Friend", 0.5)
    
    # 模拟一条干扰路径：Alice -> David (0.2，是一级直接好友)
    db.add_edge("Alice", "David", "Friend", 0.2)

    print(" ✔ 节点与关系写入完毕！SQLite 二叉有向图拓扑大盘构建成功。")

    # 3. 启动工作流二：多跳路径图扫描分析
    print("\n[🔍 多跳路径扫描分析]：查询与 'Alice' 相距两跳（中间隔着 Bob）的所有间接人脉...")
    connections = db.traverse_two_hops("Alice")

    print("\n--------------------------------------------------")
    print("[Alice 的二级社交网络大盘召回]")
    for item in connections:
        start, middle, end, heat = item
        print(f" 🔗 关系链路: {start} ➔ ({middle}) ➔ {end} | 物理间接热度: {heat:.4f}")
    print("--------------------------------------------------")

    # 自验条件：一级和二级数据完全匹配
    if len(connections) > 0 and connections[0][2] == "Charlie" and abs(connections[0][3] - 0.72) < 1e-5:
        print("[✔] 测试成功！SQLite 离线有向图建表与多跳路径关系热力扫描完全闭环！")
        sys.exit(0)
    else:
        print("[❌] 错误：图路径扫描解算偏差或多径覆盖缺失！")
        sys.exit(1)
```

### 避坑指南与图数据库天花板

#### 🛠 避坑指南：
1. **避开环形路径死循环坑**：如果 Bob 是你的好友，你是 Bob 的好友，在进行两跳扫描时，如果没有在 SQL 或代码中显式“排除起点本身”，Alice 就会查到（Alice ➔ Bob ➔ Alice）这条环路，以为自己是自己的“二级人脉”。**解决办法**：在多跳查询中，必须在 `WHERE` 条件里加上 `AND e2.to_id != e1.from_id` 强力过滤，严禁回环。
2. **避免路径大爆炸坑**：在进行 3 跳甚至 4 跳查询时，如果每个节点有 100 个好友，3 跳的搜索范围会瞬间暴增到 `100 * 100 * 100 = 100万` 次连接！这会让 SQLite 的 JOIN 发生严重的卡顿死机。**解决办法**：在多跳扫描中必须设定最大权重衰减阈值（比如关系乘积低于 0.05 路径直接剪枝丢弃），或者限制最大输出结果行数，防爆避雷。
3. **节点唯一性冲突坑**：在频繁插入人脉时，如果直接用简单的 `INSERT`，遇到重名的联系人（比如两个都叫小明）会直接把旧数据覆盖掉。**解决办法**：在真实环境下，节点表不能仅以“名字”为主键，必须结合唯一标识（如邮箱、电话或 UUID），在有向边写入时根据唯一 ID 物理挂载。

#### ⚠️ 行业瓶颈：
必须直面，用 SQL 关系型表来模拟图数据库存在着**天然的语法墙瓶颈**。
虽然查 2 跳、3 跳时写几个 `JOIN` 性能极好，但如果遇到需要“全图扫描最长路径”或者“计算不限跳数的任意两点最短距离”时，SQL 语言会变得极其臃肿和难以维护，甚至需要写递归的 CTE 语法，可读性极差。
当你的社交大盘节点数突破数百万、且需要进行复杂的图机器学习算法（如 PageRank）时，还是必须要考虑转向专业的图计算引擎（如 Neo4j 或 NetworkX）。
因此，在中小型隐私项目里用 SQL 极速起步，在大型分布式系统里用专业图引擎，才是数据架构的理智抉择！
