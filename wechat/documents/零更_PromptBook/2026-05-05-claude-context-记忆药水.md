# 给 AI 喂下记忆药水：claude-context 实操，用 MCP 协议让你的代码库变透明

> **摘要**：当你的代码达到十万行以上，连你自己都不知道那个该死的函数藏在哪，AI 就更抓瞎了。今天拆解 GitHub 上极客圈疯传的 **claude-context**。它是大模型时代的神级外挂，能让 AI 的脑容量瞬间扩充一万倍，变成对你项目了如指掌的活字典。

---

## 0. 快速认识这个“记忆扩展包”

### 📌 项目是什么？
**claude-context** 是一个基于语义搜索的 MCP（Model Context Protocol）服务器。简单来说，它就像是给你的 AI（比如 Claude Desktop）加装了一个超级雷达。当 AI 遇到不懂的问题时，它能通过这个雷达，在你那庞大的本地代码库里，瞬间定位到几百个文件深处的某一行代码。

### ❓ 为什么会有这个项目？
大模型都有“上下文窗口”限制。即使是最强的模型，也装不下你公司十几年的屎山代码。如果你直接问它：“帮我改一下用户鉴权逻辑”，它会因为不知道文件在哪而胡编乱造（幻觉）。claude-context 的诞生，是为了实现 **“按需加载”**，让 AI 只看跟当前任务最相关的代码切片。

### 🛠️ 怎么样运行运用项目？
1. **启动服务**：在本地克隆代码，跑起这个 MCP 服务端，指定它去扫描你的项目根目录。
2. **构建索引**：它会在后台静默工作，把你所有的代码解析成“语义向量”存起来。
3. **对接大脑**：在 Claude Desktop 的配置里加上它的地址。搞定！

## 1. 痛点：为什么你的 AI 总是在“胡说八道”？

AI 编程最尴尬的瞬间：
- AI 说：你需要调用 `getUserData()`。
- 你说：我项目里根本没这个函数，你丫编的吧！
因为 AI 是个瞎子，它看不到你项目里究竟定义了什么。**claude-context** 治好了 AI 的“眼盲症”。它通过向量搜索，强行给 AI 注入了绝对正确的本地背景知识。

---

## 2. 核心逻辑：向量检索与 MCP 对接 (Vector Retrieval & MCP)

### 底层逻辑本质：
claude-context 的本质是 **“把代码降维成数学坐标”**。
1. **语义切块**：它把你的文件切成一小块一小块，用嵌入模型（Embedding）把它们变成一串串数字。
2. **意图匹配**：当 AI 说“找一下订单支付模块”时，它把这句话也变成数字，然后在坐标系里找最近的代码块。
3. **MCP 桥梁**：找到代码后，通过标准化的 MCP 协议，无缝塞进 AI 当前的对话窗口中。

## 3. 手把手操作：3 分钟打造你的“超级大脑”

### Step 1：生成代码向量系
运行工具，让它扫描那个你刚接手、完全看不懂的老旧项目。这可能需要喝杯茶的时间，因为它是字面意义上在“阅读”每一行代码。

### Step 2：触发语义搜索
打开 Claude Desktop。输入：“我在前端点了一下‘购买’，后端到底哪几个文件会响应？”

### Step 3：见证奇迹
Claude 不会让你去贴代码。它会通过 claude-context，自动去本地发起 5 次检索，然后告诉你：“请求先经过了 `router.js`，然后触发了 `payment.ts`，最终在 `db_util.go` 里存盘。”整个逻辑链路清清楚楚。

## 5. 价值提示词：榨干超级大脑的最后一点算力

既然 AI 已经掌握了全局信息，你就可以提更尖锐的问题了。收下这份**架构师盘问指令**：

```markdown
# Role: 代码库审查法官 (Codebase Inquisitor)
# Context: 你现在通过 claude-context 获取了本项目的全量向量索引权限。
# Logic:
1. **深挖暗桩**: 我需要你搜索所有与 [支付状态扭转] 相关的代码，找出潜在的竞争条件 (Race Condition)。
2. **链路溯源**: 不要给我看浅层的 API 定义。请顺藤摸瓜，把从 Controller 到 Database 的完整调用堆栈挖出来。
3. **消除冗余**: 查一下这个类里面，有哪些方法在全网都没被调用过（死代码），列出清理清单。
4. **底层本质**: 从高内聚低耦合的角度，锐评一下目前工程结构的糟糕之处。
```

## 6. 多角度分析：MCP 到底改变了什么？

- **从交互看**：以前是我们人去找资料喂给 AI；现在是 AI 自己长了手脚去翻我们的抽屉。
