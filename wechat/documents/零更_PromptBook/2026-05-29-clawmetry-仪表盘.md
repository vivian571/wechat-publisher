## 3. 核心本质：终端 ANSI 渲染与阈值主动切断的“两大物理铁律”

这套大模型用量监控网关之所以能做到铁面无私，全靠底层两大架构铁律的绝对保障：

### 铁律一：基于 ANSI Escape Codes 的端侧富文本流式渲染（Fidelity CLI Rendering）
我们不需要引入臃肿的第三方图形库或架设 Web 前端。通过操作系统原生的 **ANSI 转义字符**（如 `\033[1;31m` 表示亮红，`\033[1;32m` 表示亮绿），我们在最基础的控制台上就能画出极高画质的双线边框表格与渐变色用量条。
**这是一种完全端侧本地化、时间复杂度 $O(1)$、零三方依赖的极客美学，可以在任意微弱的终端上平稳跑出炫酷的科技感！**

### 铁律二：增量累加器与强制主动熔断跳闸（Incremental Aggregation & Process Hard-Stop）
每一轮 API 交互结束，或者是流式输出接收到 Token 碎片时，引擎都会增量累加当前花费：
$$\text{TotalCost} = \text{PromptTokens} \times \text{Price}_P + \text{CompletionTokens} \times \text{Price}_C$$
一旦该值超过设定的**“硬限预算大闸（Hard Budget Limit）”**，引擎会绕过任何中间层逻辑，直接向系统发送 `sys.exit(1)` 或强行抛出熔断异常。
**这是一种不给任何借口、物理级别的主动终止，从根源上拦截失控大模型的财务大崩盘！**

COLOR_GREEN = "\033[1;32m"
COLOR_YELLOW = "\033[1;33m"
COLOR_RED = "\033[1;31m"
COLOR_CYAN = "\033[1;36m"
COLOR_RESET = "\033[0m"

class ClawmetryDashboard:
    def __init__(self, hard_budget_limit=5.0):
        # 设定硬性最高预算上限（单位：元）
        self.budget_limit = hard_budget_limit
        self.accumulated_cost = 0.0
        self.total_prompt_tokens = 0
        self.total_completion_tokens = 0

    def print_telemetry_table(self, last_step_name, new_prompt, new_completion, step_cost):
        """工作流一：拦截 API 状态并在控制台格式化输出高画质彩色 CLI 富文本表格"""
        self.total_prompt_tokens += new_prompt
        self.total_completion_tokens += new_completion
        self.accumulated_cost += step_cost
        
        # 计算当前的预算消耗比例
        usage_percent = min((self.accumulated_cost / self.budget_limit) * 100.0, 100.0)
        progress_bar_length = 20
        filled_length = int(progress_bar_length * usage_percent / 100.0)
        
        # 动态配色进度条：安全绿色 -> 警告黄色 -> 危险红色
        bar_color = COLOR_GREEN
        if usage_percent > 80.0:
            bar_color = COLOR_RED
        elif usage_percent > 50.0:
            bar_color = COLOR_YELLOW
            
        progress_bar = bar_color + "█" * filled_length + "░" * (progress_bar_length - filled_length) + COLOR_RESET

        # 终端富文本表格双线排版构建
        print(f"\n{COLOR_CYAN}╔══════════════════════════════════════════════════════════════╗{COLOR_RESET}")
        print(f"{COLOR_CYAN}║             ⚡️ CLAWMETRY AGENT TELEMETRY MONITOR             ║{COLOR_RESET}")
        print(f"{COLOR_CYAN}╠══════════════════════════════════════════════════════════════╣{COLOR_RESET}")
        print(f" 📂 当前监控节点: {COLOR_YELLOW}{last_step_name:<44}{COLOR_RESET}")
        print(f" 📥 输入 Token: {self.total_prompt_tokens:<12} | 📤 输出 Token: {self.total_completion_tokens:<12}")
        print(f" 💰 当前节点花费: {COLOR_GREEN}¥ {step_cost:.4f}{COLOR_RESET}   | 📊 累计总花费: {COLOR_GREEN}¥ {self.accumulated_cost:.4f}{COLOR_RESET}")
        print(f" 🔒 警戒预警线: {COLOR_RED}¥ {self.budget_limit:.4f}{COLOR_RESET}   | 📈 预算用量条: [{progress_bar}] {usage_percent:.1f}%")
        print(f"{COLOR_CYAN}╚══════════════════════════════════════════════════════════════╝{COLOR_RESET}")


class TokenBudgetBreaker:
    def __init__(self, dashboard):
        self.dashboard = dashboard

    def enforce_safety_check(self):
        """工作流二：关联 Token 预算大闸，一旦超标触发红色高亮警报并强行熔断拉闸"""
        if self.dashboard.accumulated_cost >= self.dashboard.budget_limit:
            print(f"\n{COLOR_RED}╔══════════════════════════════════════════════════════════════╗")
            print(f"║ 🚨 [FATAL BREAKER ACTIVATE] 预算超标！安全大闸物理熔断拉闸！ ║")
            print(f"╠══════════════════════════════════════════════════════════════╣")
            print(f"║ -> 设定最大上限: ¥ {self.dashboard.budget_limit:.4f}                               ║")
            print(f"║ -> 瞬时真实花费: ¥ {self.dashboard.accumulated_cost:.4f}                               ║")
            print(f"║ -> 进程正在被强制拉闸强行终止，彻底掐死失控死循环！         ║")
            print(f"╚══════════════════════════════════════════════════════════════╝{COLOR_RESET}\n")
            
            # 物理拉闸：抛出 SystemExit 强行退出进程，返回状态码 99
            sys.exit(99)


# ==================== 仿真 Agent 失控死循环与跳闸测试入口 ====================
if __name__ == "__main__":
    print("[⚙] 正在初始化 clawmetry 智能体成本用量控制仪表盘与熔断系统...")
    
    # 模拟预算上限仅为 0.1 元，便于在循环仿真中迅速触发物理熔断
    dashboard = ClawmetryDashboard(hard_budget_limit=0.1000)

    # 模拟一个因为思维逻辑“鬼打墙”而陷入无限循环调用昂贵接口的失控 Agent

    print("[💀 警报区] 模拟 Agent 规划发生逻辑抽风，陷入后台死循环调用接口...")
    time.sleep(0.5)

    step_counter = 1
    try:
        while True:
            # 仿真每次 API 调用的真实 Token 消耗量与产生的费用
            mock_prompt = 1500

            # 仿真计算节点花费，每次调用耗费 0.0350 元

## 6. 避坑指南：终端富文本渲染与熔断的三大隐形暗雷

* **避坑 1：非标准控制台导致的“乱码脏数据灾难”。** 如果你的 Agent 是部署在没有标准虚拟终端环境的非交互式后台（如 Docker 纯后台进程、Jenkins 构建终端），原生的 ANSI 字符（如 `\033[1;32m`）会直接被当作普通文本打印出来，导致你的日志文件被塞满混乱的乱码脏数据。**在初始化仪表盘时，必须检测当前终端的类型（如 `sys.stdout.isatty()`），如果是非交互终端，自动降级为“物理纯文本模式（Clean Plaintext Mode）”，擦除所有 ANSI 转移字符！**
* **避坑 2：多进程并发下控制台乱序排版崩溃。** 当你启动了 5 个并行的子 Agent 且都在往同一个 stdout 写入数据时，不同进程的 ANSI 字符和表格边框会疯狂交织在一起，画面极其错乱恶心。**多进程模式下，必须使用“线程/进程安全锁（Lock）”或者是统一的集中式“日志管道渲染代理（Telemetry Logger Agent）”，保证每次表格输出都是绝对原子的（Atomic Print）！**
* **避坑 3：只监控大模型费用而忽略“三方 API 嵌套收费”导致的漏判。** 许多开发者只去拦截大模型的输入输出 Token 费用。但如果 Agent 调用的三方工具（如 Google 搜索一次收费 0.05 元、人脸识别一次收费 0.2 元）也在疯狂循环，账单同样会炸裂。**成本计算引擎必须设计成“开放多维成本插件架构（Multi-source Cost Aggregator）”，将大模型 Token 价格和三方 Tool API 调用单次费用进行统一增量累加，守护全防线！**
