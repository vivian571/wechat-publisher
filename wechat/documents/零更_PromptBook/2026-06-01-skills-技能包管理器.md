### 底层透视：什么是绝对安全的“代码沙箱”？

我们经常在各种 Agent 框架里听到“沙箱（Sandbox）”这个词。
简单来说，沙箱就是一个**与世隔离的虚幻世界**。
在 Python 里，运行代码最直接的办法就是用 `exec(code_str)`。
但如果直接运行 `exec`，大模型写的代码就可以任意访问你的物理硬盘、修改系统变量、甚至进行网络攻击。
这是因为 `exec` 默认共享了你当前运行环境的全局命名空间（`globals()`）和内置函数（`__builtins__`），其中就包含了高危的 `__import__` 算子。
我们要做的，就是手搓一个**无尘密闭净化室**：
1. **剥夺特权**：我们重新定制一个空底座的 `__builtins__`，只塞入 `print`、`len` 等绝对安全的纯数学算子，彻底把 `__import__`、`open`、`eval` 等高危红线武器扫地出门！
2. **闭环运行**：大模型写的代码只能在这个被严重阉割的阉割版命名空间下运行。哪怕它写了 `import os`，沙箱也会直接抛出 `NameError: name 'import' is not defined`，让所有恶意攻击胎死腹中。
3. **用量限额**：在沙箱里注入一个只读的“打卡审计算子”。代码每运行一次繁重的 API 翻译，就必须强制“打卡扣费”。一旦累积 Token 超过了 YAML 里面设定的安全配额，熔断大闸瞬间拉下，强制终止程序！

### 双星连珠：YAML 静态解析与沙箱 Token 物理审计大闸

本管理系统由两个紧密衔接的物理工作流构成：

1. **工作流一：静态 Manifest 技能 YAML 解析器（YAMLManifestParser）**
   专门读取技能包的声明文件。为了保持零外部依赖，我们手搓了一个极其优雅的 YAML 状态机，精准分离出技能名、版本号、安全 Token 限额以及核心多行 Python 代码块。

2. **工作流二：受控沙盒执行与 Token 审计引擎（SandboxedSkillExecutor）**
   物理搭建沙箱全局命名空间，注入 Token 消耗追踪闭包。采用物理异常拦截，让超额调用与非法导入在执行到第一行时就被安全锁死。

### 极简源码：手搓 100 行声明式技能运行器

请将以下完整源码保存为 `skills_manager.py`。全程零第三方包，纯 Python 物理自验，macOS 一键安全拉起！

```python
import sys

class YAMLManifestParser:
    """智能体技能清单极简 YAML 解析器"""
    def __init__(self):
        pass

    def parse_manifest(self, yaml_text):
        """
        工作流一：静态解析技能 YAML 清单。
        提取技能包名称、描述、Token 限制以及嵌入的沙盒执行代码。
        """
        config = {}
        in_code_block = False
        code_lines = []

        for line in yaml_text.splitlines():
            # 处理多行代码块字段标志 code: |
            if in_code_block:
                # 假设核心执行代码行带有前置空格缩进
                if line.startswith("  ") or line.strip() == "":
                    # 去掉前置的 2 个空格缩进，恢复原始物理代码行
                    code_lines.append(line[2:] if line.startswith("  ") else line)
                    continue
                else:
                    in_code_block = False
                    config["code"] = "\n".join(code_lines)
            
            stripped = line.strip()
            if not stripped or stripped.startswith("#"):
                continue

            if ":" in stripped and not in_code_block:
                key, val = stripped.split(":", 1)
                key = key.strip()
                val = val.strip()
                if val == "|":
                    in_code_block = True
                    code_lines = []
                else:
                    # 去掉物理字符串两边的引号
                    if (val.startswith('"') and val.endswith('"')) or (val.startswith("'") and val.endswith("'")):
                        val = val[1:-1]
                    config[key] = val

        if in_code_block and code_lines:
            config["code"] = "\n".join(code_lines)

        return config

class SandboxedSkillExecutor:
    """沙盒命名空间安全执行与 Token 物理审计引擎"""
    def __init__(self, token_limit=150):
        self.token_limit = token_limit

    def run_sandbox_code(self, code_str, context_data):
        """
        工作流二：受控沙盒运行与 Token 额度实时卡口审计。
        在完全隔离的 globals/locals 环境下，注入受控安全算子。
        """
        # 构建完全隔离的安全内置函数库，阻断一切 __import__ 和 os/sys 敏感系统操作
        sandbox_globals = {
            "__builtins__": {
                "print": print,
                "range": range,
                "len": len,
                "abs": abs,
                "int": int,
                "float": float,
                "str": str,
                "list": list,
                "dict": dict
            }
        }
        
        # 审计用量闭包，注入沙盒
        audit_state = {
            "tokens_consumed": 0,
            "limit": self.token_limit
        }

        def spend_tokens(count):
            """受控审计算子：每次大模型调用或重度运算需打卡扣除"""
            audit_state["tokens_consumed"] += count
            if audit_state["tokens_consumed"] > audit_state["limit"]:
                raise PermissionError(f"🚨 [Token 熔断] 额度耗尽！已消耗 {audit_state['tokens_consumed']}，上限 {audit_state['limit']}！")
            print(f" 💰 [Token 审计] 消耗 {count} Tokens | 剩余: {audit_state['limit'] - audit_state['tokens_consumed']}")

        # 注入用户上下文与安全审计算子
        sandbox_locals = {
            "input_data": context_data,
            "spend_tokens": spend_tokens,
            "result": None
        }

        try:
            # 物理 exec 安全编译执行
            exec(code_str, sandbox_globals, sandbox_locals)
            return {
                "success": True,
                "output": sandbox_locals.get("result"),
                "tokens_used": audit_state["tokens_consumed"]
            }
        except Exception as e:
            return {
                "success": False,
                "error": str(e),
                "tokens_used": audit_state["tokens_consumed"]
            }

if __name__ == "__main__":
    print("[⚙] 正在启动智能体声明式技能包加载管理器自验程序...")

    # 1. 模拟一个声明式的 YAML 技能配置文件
    manifest_yaml = """
name: "TranslationSkill"
version: "1.0.0"
token_limit: "100"
code: |
  # 从上下文输入提取源文本
  text = input_data.get("text", "")
  words = text.split()
  
  # 模拟翻译每个单词，每个词消耗 25 个 Token
  for w in words:
      spend_tokens(25)
      
  result = f"Translated: {text}"
"""
    
    # 2. 执行工作流一：YAML 解析
    parser = YAMLManifestParser()
    parsed_config = parser.parse_manifest(manifest_yaml)
    
    print("\n[演示一：声明式 YAML 清单配置提取]")
    print(f" 📂 技能名称: {parsed_config.get('name')}")
    print(f" 📂 预设 Token 限制: {parsed_config.get('token_limit')}")
    print(" 📂 解析出的核心执行代码:")
    print("--------------------------------------------------")
    print(parsed_config.get("code"))
    print("--------------------------------------------------")

    # 3. 执行工作流二：受控沙盒环境下的执行与审计
    print("\n[演示二：沙盒沙箱运行与 Token 用量熔断测试]")
    
    # 正常运行测试
    token_limit = int(parsed_config.get("token_limit", 100))
    executor = SandboxedSkillExecutor(token_limit=token_limit)
    
    # 输入待翻译文本，包含 3 个单词 (预计消耗 75 tokens < 100，安全通过)
    input_ok = {"text": "hello agent world"}
    res_ok = executor.run_sandbox_code(parsed_config["code"], input_ok)
    
    print(f" ✔ [用量安全情况] 执行成功: {res_ok['success']} | 输出结果: {res_ok['output']} | 消耗 Token: {res_ok['tokens_used']}")

    # 熔断运行测试
    # 输入待翻译文本，包含 5 个单词 (预计消耗 125 tokens > 100，触发熔断大闸)
    input_over = {"text": "hello agent world extra words"}
    res_over = executor.run_sandbox_code(parsed_config["code"], input_over)
    
    print(f" ✔ [用量超载情况] 执行成功: {res_over['success']} | 拦截错误: {res_over['error']} | 消耗 Token: {res_over['tokens_used']}")

    # 自验条件
    if res_ok["success"] and not res_over["success"] and "Token 熔断" in res_over["error"]:
        print("\n[✔] 自验成功！Manifest 静态 YAML 解析与受控沙盒 Token 审计双工作流 100% 成功！")
        sys.exit(0)
    else:
        print("\n[❌] 错误：沙盒未熔断或者 YAML 解析数据倾斜！")
        sys.exit(1)
```

### 避坑指南与沙箱天花板

#### 🛠 避坑指南：
1. **避开内置函数被窃取坑**：在 Python 中，即使你屏蔽了 `__builtins__`，沙箱里的代码仍然可以通过一些高级黑客技巧（比如利用浮点数或字符串的 `.__class__.__base__.__subclasses__()` 链条）顺藤摸瓜，重新在内存中反弹拿到 `os` 模块进行越狱。**解决办法**：在执行 `exec` 之前，必须对大模型写的代码进行**静态 AST（抽象语法树，Abstract Syntax Tree）扫描**，凡是代码中包含 `__` 双下划线、`subclasses` 等黑客特征词的，在大闸编译阶段就直接一票否决，绝不进入沙箱执行！
2. **避开死循环挂死 CPU 坑**：如果大模型写的代码里包含了一个 `while True: pass` 的绝对死循环，虽然它拿不到系统特权，但它会瞬间吃满你的 CPU 单核到 100%，导致你的物理服务器因热载荷崩溃。**解决办法**：在多租户生产环境下，绝不能直接在主线程里跑 `exec`。必须将其扔进单独的子进程运行，并在外部线程使用 `signal.alarm()` 或 `subprocess` 的 `timeout` 机制，一旦运行超出 1.5 秒强制掐死（Kill）该子进程。
3. **避开浮点数累加 Token 溢出坑**：有些同学用浮点数来统计 Token 扣除比例（比如扣除 `0.33` 个），频繁加减会导致浮点数精度丢失，积累出极小的负数或溢出，产生计算漂移。**解决办法**：统一将 Token 换算成最小整数单位（如 1 Token 或 10 Tokens）进行纯整数加减计算，严防浮点精度坑。

#### ⚠️ 行业瓶颈：
必须警惕，纯 Python 原生命名空间沙箱**属于“软沙箱”技术**。
它在应用层防范大模型写错代码、防范普通的逻辑注入效果极佳，但由于它和宿主机共享同一个 Python 解释器进程（Process），它无法防范底层的 C 语言解释器缓冲区溢出攻击等“系统级越狱”。
因此，如果你的 Agent 平台要承接海量来自公网陌生用户的完全未经过滤的未知脚本，最稳妥的做法仍然是在你的 Python 软沙盒外层，套上一层 Docker 容器或者极轻量的 MicroVM（如 Firecracker），内柔外刚，双重重装保护，才是安全架构的终极解法！
