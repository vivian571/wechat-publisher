### 底层逻辑大拆解：不占手机，它是怎么在云端保持微信“灵魂在线”的？

有些对网络协议不太了解的同学会问：“老师，微信的官方限制那么多，这个 WechatOnCloud 到底是怎么绕过物理设备，实现在云端安家落户的？”
其实，它底层的核心魔法说白了就是两招：**协议虚拟化**与**云端持久长连接**。

1. **iPad 协议栈模拟（Protocol Virtualization）：**
   微信官方是不允许网页版登录的。
   WechatOnCloud 巧妙地在后台模拟了**iPad 版微信**的硬件特征与网络心跳包。
   在微信官方看来，你只是在一部挂在云端机房里的 iPad 设备上登录了微信。
   这极大地降低了被官方判定为“非正常客户端登录”而封号的风险。
2. **Docker 容器隔离与 Session 保持（Dockerized Session Keepalive）：**
   传统的扫码登录，一断网登录凭证（Cookie/Token）就失效了。
   WechatOnCloud 把整个微信通信协议栈封装在一个独立的 Docker 容器里。
   通过加密的 SQLite 本地数据库，在内存中持久化保存你的登录会话（Session）。
   即使云端服务器临时重启，它也能在极短的时间内自动读取会话缓存，重新发起握手连接，实现几乎无感的“断线自动重连”。

### 保姆级实操：三步让你的微信化身“云端赛博分身”

准备好一台便宜的云服务器（甚至是你家里的 NAS），我们马上开始部署：

#### 第一步：准备 Docker 环境
确保你的服务器里已经安装好了 Docker 和 Docker Compose。如果还没有，在 Ubuntu 服务器上运行一行命令极速安装：
```bash
curl -fsSL https://get.docker.com | bash
```

#### 第二步：编写配置文件并一键启动
1. 在你的服务器新建一个工作目录并进入：
   ```bash
   mkdir wechat-on-cloud && cd wechat-on-cloud
   ```
2. 新建一个 `docker-compose.yml` 文件：
   ```yaml
   version: '3.8'
   services:
     wechat-gateway:
       image: gloridust/wechatoncloud:latest
       container_name: wechat_gateway
       ports:
         - "8080:8080"
       environment:
         - API_KEY=your_secure_api_key  # 设置你调用机器人的 API 密钥
         - LLM_PROVIDER=openai           # 绑定你想对接的 AI 服务商（如 openai, deepseek）
         - LLM_API_KEY=sk-xxxx           # 填入你的大模型 API 密钥
       volumes:
         - ./data:/app/data             # 会话数据持久化，防止重启后重新扫码
       restart: always
   ```
3. 保存后，在终端一键唤醒容器：
   ```bash
   docker compose up -d
   ```

#### 第三步：扫码登录与测试
1. 容器运行后，访问你的服务器 IP 地址端口（如 `http://你的服务器IP:8080`），你会看到一个清爽的后台页面，上面赫然印着一个微信登录二维码。
2. 掏出手机微信，扫描该二维码，确认登录 iPad 微信。
3. 扫码成功后，后台会自动接管你的微信。
   试着用别的小号给这个微信发一句“你好”，AI 助手会在毫秒内以极度自然的语气进行自动回复。此时，你哪怕把手机关机，这个云端机器人依然在 24 小时勤恳工作！
