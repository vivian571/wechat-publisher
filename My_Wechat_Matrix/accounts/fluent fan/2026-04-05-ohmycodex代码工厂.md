## 🧐 组织拆解：谁在我的“数字工厂”里干活？

在 oh-my-codex 的世界里，你不再是写代码的，你是“厂长”。

你的工厂组织架构如下：

- **首席架构师 (Lead Architect)**：他在 `.omx/roles/arch.json` 里。他负责把你的模糊需求拆成 $ralplan（极速计划）。他不出代码，只出逻辑。
- **特种兵程序员 (Elite Coder)**：他在 `.omx/roles/coder.json` 里。他只根据架构师的计划干活，专注 TDD（测试驱动开发），不通过测试的代码他自己就会回滚。
- **逻辑质检员 (QA Auditor)**：他在 `.omx/roles/qa.json` 里。他负责挑刺。如果代码跑通了但写得不优雅，他会直接打回去重写。
- **战情室 HUD**：他在你的终端里。oh-my-codex 给原本黑乎乎的命令行加了个“实时仪表盘”，谁在思考、谁在执行、谁在报错，一目了然。

## 🔄 工作流复盘：一个 Bug 的“死亡旅行”

昨天下午，项目上线前发现一个诡异的路径遍历漏洞。

**17:00**：我在终端输入 `/plugin execute $deep-interview 找出项目里的路径安全漏洞并修复。`
**17:01**：**[面试官 Agent]** 启动。它没有直接去改代码，而是反向问了我 3 个问题：“是所有的 API 都要查，还是只查 v2 接口？”“是否需要兼容 Windows 路径？”通过这一轮 $interview，它锁定了一个之前被忽略的 edge case。
**17:05**：**[架构师 Agent]** 接手。他产出了一个 5 步修复计划。
**17:10**：**[程序员 Agent]** 并行开启 3 个副本。Agent A 重构路由，Agent B 加入沙盒过滤，Agent C 补全安全测试。
**17:25**：所有的 `PASS` 绿灯亮起。oh-my-codex 自动执行 `git commit -m "Security: path traversal fixed by omx-team"`。

**全过程我没看一眼代码逻辑，只关注了 Agent 发起的确认弹窗。**

## 💎 底层秘密：那个名为 `.omx/` 的灵魂文件夹

oh-my-codex 之所以强，是因为它把所有的“聪明才智”都结构化了。

在你的项目根目录下，有一个隐藏的 `.omx/` 目录。这是整个工厂的**“指挥部”**。

核心灵魂文件示例：`.omx/roles/architect.json`
```json
{
  "name": "Extreme Architect",
  "mission": "把需求颗粒化，确保每个任务在 5 分钟内可交付",
  "logic_gate": {
    "before_action": "必须执行 $deep-interview 确认边界",
    "after_action": "生成 $verification_checklist"
  },
  "constraints": "禁止使用废话，禁止生成重复的代码模式"
}
```

**为什么这样设计？**
因为 AI 会疲劳、会幻觉。但如果你给它规定了“逻辑门（Logic Gate）”，它在输出前必须自我 Check，这就是为什么 OmX 的交付成功率比直接问原生 AI 高出 300% 的底层本质。

## 🛠️ 上手建议：新手怎么先搞起“前 3 人”团队？

别被复杂的配置吓到，先从这 3 个最核心的角色搭起：

1. **先搞个“嘴严”的架构师**：重点配置它的反向提问能力。
2. **再搞个“手快”的程序员**：重点配置它的 TDD（测试驱动）逻辑。
3. **最后搞个“HUD 仪表盘”**：让你能看见它们在干嘛，不仅是为了监控，更是为了“调教”时的手感。

不要一上来就搞 100 个 Agent，先让这两个人能互相配合好。
