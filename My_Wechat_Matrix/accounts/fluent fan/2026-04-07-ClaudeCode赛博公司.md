## 🧐 角色拆解：谁在我的“终端指挥部”里干活？

在 Claude Code 的世界里，你不再是写代码的，你是“首席架构师”。

你的团队组织架构如下：

- **侦察总长 (Context Explorer)**：它不是盲目写的。当你下达指令，它会先调用 `ls`, `cat`, `grep`。它比你更清楚你的 `utils` 文件夹里到底藏了多少陈年旧屎。
- **主力攻坚手 (Executor Agent)**：它直接拿到了文件的“编辑权”。它不是给你段代码让你粘贴，它是直接把改好的文件存盘。
- **冷面质检员 (Test Runner)**：写完代码，它会主动执行 `git status` 和你项目里的测试脚本。报错了？它自己回去修，修不好不跟你汇报。

**14:20**：所有的测试绿灯亮起。Claude Code 自动执行了 `git add .` 并写了一份详尽的 `commit message`。

**全过程我没看一眼代码逻辑，只关注了 Agent 发起的安全确认。**

## 💎 底层秘密：那个名为 `.claudecode/` 的核心灵魂

Claude Code 之所以比普通 AI 聪明，是因为它拥有了**“物理生存空间”**。

在你的项目根目录下，它会根据你的历史偏好和当前项目结构构建临时的“认知模型”。

核心灵魂配置（思维快照）：

```json
{
  "project_context": "Next.js + Prisma + Tailwind",
  "reliability_threshold": 0.95,
  "execution_policy": "Test_Driven_First",
  "forbidden_zones": ["/archive", "/dist"]
}
```

**为什么这样设计？**
因为 AI 如果没有“边界感”，它会因为过度自信而把你的整个磁盘搅乱。Claude Code 的底层本质是**“有监督的自主性”**。它在逻辑门（Logic Gate）前必须停下来向你索要 `Permission`，这就是它敢于直接改你源码的底气。

## 🛠️ 上手建议：普通人如何先搭出“第一个分身”？

别被复杂的配置吓到，先从这 3 个最核心的配置搞起：

1. **先装好终端原件**：`npm install -g @anthropic-ai/claude-code`。
2. **给它“开天眼”**：确保你在项目根目录，先执行一次 `claude init`。
3. **设置“安全绳”**：在初次对话时输入 `“在执行任何写操作前必须询问我”`，这能保住你的项目不被整丢。

不要一上来就搞大工程，先让它帮你写一个 `README.md` 找找手感。
