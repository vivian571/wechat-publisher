【参考文章1 - Python技巧】

今天聊一个Python的"冷知识"：为什么 `[] * 3` 和 `[[] for _ in range(3)]` 结果不一样？

先看代码：

```python
# 方法1
list1 = [[]] * 3
list1[0].append(1)
print(list1)  # [[1], [1], [1]]  ← 为什么三个都变了？

# 方法2
list2 = [[] for _ in range(3)]
list2[0].append(1)
print(list2)  # [[1], [], []]  ← 这才是我们想要的
```

**原因**：

`[] * 3` 创建的是**同一个列表的3个引用**，就像3个人指向同一个房间。
`[[] for _ in range(3)]` 创建的是**3个不同的列表**，就像3个独立的房间。

💡 **记住**：
- 需要独立对象时，用列表推导式
- 只是重复简单值（数字、字符串）时，用 `*` 没问题

【参考文章2 - 性能优化】

上周帮同事优化了一段代码，性能提升了10倍。

原代码：
```python
# 慢版本 - 每次都重新计算
def get_user_info(user_id):
    # 查询数据库（耗时操作）
    return db.query(f"SELECT * FROM users WHERE id={user_id}")

for user_id in user_ids:
    info = get_user_info(user_id)
    process(info)
```

优化后：
```python
# 快版本 - 批量查询
def get_users_info(user_ids):
    # 一次查询所有数据
    return db.query(f"SELECT * FROM users WHERE id IN ({','.join(map(str, user_ids))})")

users_info = get_users_info(user_ids)
for info in users_info:
    process(info)
```

**性能对比**：
- 慢版本：1000次数据库查询
- 快版本：1次数据库查询

🚀 **优化原则**：
1. 减少I/O操作（数据库、文件、网络）
2. 批量处理优于逐个处理
3. 先测量，再优化（不要过早优化）

【参考文章3 - 设计模式】

很多人觉得设计模式很"高大上"，其实你可能每天都在用。

比如**单例模式**，听起来很复杂，但其实就是"全局只有一个实例"。

生活中的例子：
- 一个公司只有一个CEO
- 一台电脑只有一个操作系统

代码实现：
```python
class Database:
    _instance = None
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            # 初始化数据库连接
            cls._instance.connection = create_connection()
        return cls._instance

# 无论创建多少次，都是同一个对象
db1 = Database()
db2 = Database()
print(db1 is db2)  # True
```

**为什么要用单例？**
- 节省资源（数据库连接很贵）
- 保证一致性（所有地方用的是同一个连接）

⚡ **记住**：设计模式不是为了炫技，而是为了解决实际问题。
